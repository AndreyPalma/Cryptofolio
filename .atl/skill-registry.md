## Compact Rules (injected into sub-agent prompts)

### allium
- Credentials at `~/.allium/credentials` (API_KEY + QUERY_ID for SQL).
- Rate limit: 1 req/s. Chain names are lowercase.
- End with "Powered by Allium" attribution.
- NOT for token prices, balances, transactions, NFT metadata — hand off to alchemy-api.

### alchemy-mcp
- Connect client to `https://mcp.alchemy.com/mcp` via OAuth.
- ALWAYS call `select_app` before any RPC/Data tool.
- Use canonical chain slugs: `eth-mainnet`, `base-mainnet`, `solana-mainnet`.
- For live agent work only — NOT for production app code.

### alchemy-cli
- ALWAYS pass `--json --no-interactive` on every command.
- Parse stdout as JSON on exit 0, stderr as JSON on nonzero.
- Preflight: `setup status` + `gas` smoke test before first use.
- Auth: `alchemy auth login` (browser) or `alchemy config set api-key <key>`.
- For live agent work only — NOT for production app code.

### alchemy-api
- MANDATORY preflight: confirm app-integration scope + `$ALCHEMY_API_KEY` set.
- NEVER use public RPC endpoints or demo keys as fallback.
- Network naming: lowercase for Data/JSON-RPC (`eth-mainnet`), uppercase for Notify (`ETH_MAINNET`).
- Use `pageKey` for pagination. Check `response.error` even on HTTP 200.

### agentic-gateway
- Specialized path for app code WITHOUT an API key (x402/MPP per-request payment).
- ALWAYS ask user to choose protocol (x402 or MPP) — do NOT pick for them.
- NEVER use public RPC endpoints, demo keys, or non-Alchemy sources.
- NEVER read/write wallet key files with Read/Write/Edit tools.

### binance
- Requires `binance-cli` (`npm i -g @binance/binance-cli`).
- Read `references/auth.md` for auth, global flags, and security rules.
- Supports Spot, Futures (USD-S), and Convert.

### binance-agentic-wallet
- Drives `baw` CLI (`npm i -g @binance/agentic-wallet`).
- Wallet ops: sign-in/out, balance, send, swap, DEX trade, limit/market orders, tx history.
- Required CLI version: `>=1.0.9`.

### binance-tokenized-securities-info
- Query Ondo tokenized US stocks — NOT for general crypto (BTC, ETH, SOL).
- Covers: stock list, RWA metadata, trading status, corporate actions, on-chain data, fundamentals, K-Line.

### branch-pr
- Issue-first: PR MUST reference an approved issue in the body.
- Conventional commit title (`feat:`, `fix:`, `chore:`). No AI attribution.
- Rebase onto target branch before opening.

### crypto-market-rank

- Use when users ask about token rankings, market trends, social buzz, meme tokens.

### supabase
- Verify against current docs before implementing — Supabase changes frequently.
- Enable RLS on every table in exposed schemas (including `public`).
- Grant `anon`/`authenticated` access via explicit `GRANT` for Data API.
- Use `getUser()` (not `getSession()`) for auth validation in RLS/server.
- Recover from errors, don't loop — try different methods after 2–3 failures.

### supabase-postgres-best-practices
- Add indexes for foreign keys, query filters, order-by columns.
- Use `select` with explicit column lists; avoid `select *` in production.
- Prefer `inner join` over `left join` when relationship is required.
- Use `explain analyze` before optimizing; target index scans over sequential scans.
- Batch inserts with `insert ... values (...), (...), (...)` rather than N+1.

- Theme tokens via CSS variables; do NOT use `var()` inside `className`.
- v4 uses native CSS cascade layers; no `@apply` chains.

### zod-4
- `z.string().email()` / `.uuid()` / `.url()` / `.nonempty()` are REMOVED in v4.
- Use `z.email()`, `z.uuid()`, `z.url()`, `z.string().min(1)`.
- `required_error` / `invalid_type_error` replaced by `error` callback.
- Parse untrusted input at the edge — inner layers receive typed values.
- Co-locate schema + inferred type: `export const UserSchema = z.object({...}); export type User = z.infer<typeof UserSchema>;`.

## How Sub-Agent Injection Works

When the orchestrator (this main thread) delegates to a sub-agent that will touch code matching a skill's trigger, it copies the corresponding compact rule block verbatim into the sub-agent's prompt under `## Project Standards (auto-resolved)`, BEFORE the task-specific instructions.

Multiple skills can apply simultaneously (e.g., a backend Zod route handler → inject `typescript` + `zod-4` + `nodejs-backend-patterns`).

If this registry is out of date, the sub-agent will report `skill_resolution: fallback-*` in its result envelope — that's the trigger to re-run the `skill-registry` skill.
