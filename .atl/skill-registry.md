## Compact Rules (injected into sub-agent prompts)

### typescript (inject when sub-agent touches `.ts` / `.tsx`)

- Use `as const` objects + `typeof` type extraction for enums (never native TS `enum`).
- `strict: true` + `noUncheckedIndexedAccess: true` in tsconfig.
- Prefer `type` aliases for unions/intersections, `interface` for object shapes that may be extended.
- No `any`. Use `unknown` + narrow with Zod at boundaries.
- Named exports only; default exports banned.

### zod-4 (inject when sub-agent uses Zod)

- `z.string().email()` / `.uuid()` / `.url()` / `.nonempty()` are REMOVED in v4. Use `z.email()`, `z.uuid()`, `z.url()`, `z.string().min(1)`.
- `required_error` / `invalid_type_error` replaced by `error` callback: `z.string({ error: "..." })`.
- Parse untrusted input at the edge (HTTP handler, queue consumer) — inner layers receive typed values.
- Co-locate schema + inferred type: `export const UserSchema = z.object({...}); export type User = z.infer<typeof UserSchema>;`.

### nodejs-backend-patterns (inject for backend code)

- Fastify plugin-per-feature architecture. Register routes through plugins, not directly on the server instance.
- Error handling via Fastify `setErrorHandler` + typed domain errors — never throw strings.
- Middleware / hooks for cross-cutting concerns (auth, logging, rate-limit). Auth middleware on `/api/*` per PRD US-003.
- Use Fastify's built-in JSON schema or `fastify-type-provider-zod` to wire Zod schemas to route validation.
- Never log secrets, API keys, or JWTs. Redact in log formatters.

### react-19 (inject for frontend `.tsx`)

- NO manual `useMemo` / `useCallback` — React Compiler handles it. Writing them is a code smell.
- Use `use(Promise)` / `use(Context)` for read-at-render. Actions with `useActionState` for form flows.
- Server/client boundary is N/A (Vite SPA here), but still prefer colocated data fetching.
- `ref` is now a regular prop — no `forwardRef`.

### tailwind-4 (inject for frontend styling)

- Class first. `style={{...}}` only for dynamic computed values.
- Use `cn()` helper (from `clsx` + `tailwind-merge`) for conditional class composition.
- Theme tokens via CSS variables; do NOT use `var()` inside `className` — put it in the `style` prop or a Tailwind theme extension.
- v4 uses native CSS cascade layers; no `@apply` chains.

### branch-pr (inject when the task is opening a PR)

- Issue-first: PR must reference the originating issue in body.
- Conventional commit title (`feat:`, `fix:`, `chore:` ...). No AI attribution (project rule).
- Rebase, not merge, onto the target branch before opening.

### issue-creation (inject when creating an issue)

- Bug reports: reproduction steps, expected vs actual, environment.
- Feature requests: user story, acceptance criteria, non-goals.

### judgment-day (inject only on explicit trigger phrase)

- Launch two blind judge sub-agents in parallel on the same target, synthesize, apply fixes, re-judge; escalate after 2 iterations.

## How Sub-Agent Injection Works

When the orchestrator (this main thread) delegates to a sub-agent that will touch code matching a skill's trigger, it copies the corresponding compact rule block verbatim into the sub-agent's prompt under `## Project Standards (auto-resolved)`, BEFORE the task-specific instructions.

Multiple skills can apply simultaneously (e.g., a backend Zod route handler → inject `typescript` + `zod-4` + `nodejs-backend-patterns`).

If this registry is out of date, the sub-agent will report `skill_resolution: fallback-*` in its result envelope — that's the trigger to re-run the `skill-registry` skill.
