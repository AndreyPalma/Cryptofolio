**wallets** — `id, user_id, wallet_type (ON_CHAIN|CEX), address, network (ETH|BSC|CEX_BINANCE), label, last_synced_at, created_at`
- CHECK: ON_CHAIN → address NOT NULL + network ∈ {ETH,BSC}; CEX → address IS NULL + network=CEX_BINANCE

## Position Engine Interface

Exported from `apps/backend/src/position-engine/index.ts`:

```
processTransaction(input: ProcessTransactionInput): PositionEngineResult
calculateWAC(position: PositionState, currentPriceUsd?: DecimalString | null): WACResult
```

Types:
- `PositionState` — `{ id, walletId, tokenId, cycleNumber, status, balance, wac, costBasis, realizedPnlUsd, openedAt, closedAt }`
- `WACResult` — `{ wac, costBasis, balance, unrealizedPnlUsd, unrealizedPnlPct }` — computed on demand with current price
- `PositionEngineResult` — `{ position, realizedPnlDelta, positionWasOpened, positionWasClosed }`

Key observation: `calculateWAC` already accepts a `currentPriceUsd` and returns `unrealizedPnlUsd` + `unrealizedPnlPct`. This is the computation kernel for portfolio P&L — US-007 should reuse it rather than reimplementing.

## Gaps Identified

### 1. PriceService (new — not exists)
US-007 requires real-time prices from two external sources:
- **DefiLlama**: `GET /coins/prices/current/{chain}:{address}` — for ON_CHAIN tokens. chain = `ethereum` (ETH) or `bsc` (BSC).
- **Binance Public Ticker**: `GET https://api.binance.com/api/v3/ticker/price?symbol=<binance_symbol>USDT` — for CEX tokens.

Neither exists. Needs: HTTP client (Node `fetch` built-in is available in Node 18+), in-memory TTL cache (DefiLlama 60s, Binance 10s), graceful degradation returning `{ priceUnavailable: true }` on any fetch error.

No external HTTP client library is currently installed (`node-fetch`, `axios`, `got` not in package.json). Native `fetch` (Node 18+) is the zero-dependency approach.

### 2. PortfolioService (new — not exists)
The core query for `GET /api/portfolio` requires:
- Load all wallets for the user
- For each wallet, load all OPEN positions with their token data
- Group ON_CHAIN positions by `(contract_address, network)` across wallets (multi-wallet aggregation)
- Keep CEX positions as independent rows (never aggregate on-chain + CEX)
- Fetch current price for each unique token (deduped price fetches)
- Compute aggregated WAC using weighted average across wallets: `sum(balance_i * wac_i) / sum(balance_i)`
- Return the response shape defined in the AC

### 3. PositionDetailService (new or extension of transaction.ts)
For `GET /api/portfolio/token/:contractAddress/:network`:
- Find the token by (contract_address, network) — no `findByAddress` method exists on TokenService
- Find the OPEN position for that token (scoped by wallet_id if ON_CHAIN + ?wallet_id= param)
- List transactions for that position with per-lot P&L enrichment:
  - Inbound (BUY/SWAP_IN/TRANSFER_IN): `lotPnlUsd = (currentPrice - price_usd) * amount`
  - Outbound (SELL/SWAP_OUT/TRANSFER_OUT): `{ displayAs: 'Sold/Out' }`

### 4. CycleHistoryService (new or extension)
For `GET /api/portfolio/token/:contractAddress/:network/history`:
- Query CLOSED positions for that token (and optional wallet_id)
- Return `{ cycleNumber, openedAt, closedAt, realizedPnlUsd }`

### 5. Missing TokenService method
Need `findByContractAddress(pool, contractAddress, network): Promise<Token | null>` — used by portfolio token detail endpoint.

### 6. New route plugin
`portfolioRoutes` plugin for three routes:
- `GET /api/portfolio`
- `GET /api/portfolio/token/:contractAddress/:network`
- `GET /api/portfolio/token/:contractAddress/:network/history`

## Implementation Approach

### Architecture

Follow existing patterns: service functions receive `Pool`, routes instantiate `Pool` once and call services.

```
src/
  services/
    portfolio.ts          ← new: getPortfolioSummary(), getTokenDetail()
    price.ts              ← new: PriceService singleton with TTL cache
  routes/
    portfolio.ts          ← new: portfolioRoutes plugin (3 routes)
  types/
    portfolio.ts          ← new: PortfolioSummary, TokenPosition, PortfolioTokenRow, CycleHistory
```

### PriceService design
```typescript
// Singleton module-level cache
type CacheEntry = { priceUsd: string; expiresAt: number };
const cache = new Map<string, CacheEntry>();

async function getOnChainPrice(contractAddress: string, network: 'ETH' | 'BSC'): Promise<string | null>
async function getCexPrice(binanceSymbol: string): Promise<string | null>
export async function getPrice(token: Token): Promise<string | null>
```
Cache key: `${network}:${contractAddress.toLowerCase()}` for on-chain, `cex:${binanceSymbol.toUpperCase()}` for CEX.
On any fetch error: log warning + return `null` (caller wraps in `{ priceUnavailable: true }`).

DefiLlama chain mapping: `ETH → 'ethereum'`, `BSC → 'bsc'`.

### Portfolio Aggregation (ON_CHAIN)
Multi-wallet aggregation SQL joins positions → tokens → wallets in a single query to avoid N+1:

```sql
SELECT
  p.id, p.wallet_id, p.wac, p.balance, p.cost_basis, p.realized_pnl_usd,
  t.id AS token_id, t.symbol, t.network, t.contract_address, t.binance_symbol,
  w.wallet_type
FROM positions p
JOIN tokens t ON t.id = p.token_id
JOIN wallets w ON w.id = p.wallet_id
WHERE p.status = 'OPEN'
ORDER BY t.network, t.contract_address, t.symbol
```

In application layer:
- Group by `(contract_address, network)` for ON_CHAIN → aggregate WAC: `Σ(balance_i × wac_i) / Σbalance_i`
- CEX rows never aggregated (already single wallet by invariant)

### Per-lot P&L enrichment
Add to `listTransactions` a new variant or post-process in `portfolioService.getTokenDetail()`:
```typescript
// For each tx:
if (['BUY','SWAP_IN','TRANSFER_IN'].includes(tx.type) && tx.price_usd && currentPrice) {
  lotPnlUsd = (currentPrice - tx.price_usd) * tx.amount
}
// else: displayAs = 'Sold/Out'
```
This is pure computation — no new DB queries needed beyond the existing `listTransactions`.

### index.ts registration
```typescript
const { portfolioRoutes } = await import('./routes/portfolio.js');
await fastify.register(portfolioRoutes, { prefix: '/api/portfolio' });
```

## Risks

### R1 — N+1 on price fetching (HIGH)
If portfolio has 20 tokens and price is fetched per-token sequentially, that's 20 external HTTP calls in the critical path. Mitigation: `Promise.all` parallel price fetches + in-memory cache deduplicated by token key. Still bound by Binance/DefiLlama rate limits.

### R2 — DefiLlama batch endpoint (MEDIUM)
DefiLlama supports bulk fetch: `GET /coins/prices/current/ethereum:0x...,bsc:0x...` (comma-separated). Should use bulk for ON_CHAIN tokens to reduce to 1 HTTP call per network. PRD only describes the single-token URL — confirm batch is acceptable.

### R3 — Aggregated WAC precision (MEDIUM)
Weighted average across wallets uses decimal.js (same as engine). Must NOT use JavaScript float math. Reuse `toDecimal()` and `roundToStorage()` from `decimal-utils.ts` for all portfolio aggregations.

### R4 — CEX token missing binance_symbol (LOW)
If a CEX token was created without `binance_symbol`, the Binance ticker call has no symbol to use. Guard: if `binance_symbol` is null → treat as priceUnavailable. This is a data quality issue, not a crash.

### R5 — Token not found by (contractAddress, network) (LOW)
The detail endpoint uses URL params. If the token doesn't exist in DB, return 404. Need `findByContractAddress` on TokenService — currently missing.

### R6 — Multiple OPEN positions per (wallet, token) (LOW — but verify)
Current engine design: only one OPEN position per (wallet_id, token_id) at a time (enforced by `createTransaction` logic). The portfolio query can safely use `WHERE status = 'OPEN'` with no ambiguity. However, this should be verified — there is no DB UNIQUE constraint on (wallet_id, token_id) WHERE status='OPEN'; it's logic-level only.
